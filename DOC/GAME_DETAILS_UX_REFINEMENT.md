## 第一批：让三个常用入口容易找到

目标布局：左栏为完整封面及右上角的图片编辑按钮；右栏首行从左到右为「仙剑奇侠传」「编辑名称」铅笔和靠右的「更多操作 ▾」。在宽窗口中，额外空间留在铅笔与菜单之间；窄窗口允许长标题换行，菜单仍在标题区。

| 入口 | 当前表现 | 实施与验收 |
| --- | --- | --- |
| 管理游戏图片 | 方形土星封面放进固定 3∶4 容器，上下留灰边。普通图片图标位于上方灰边，点击后进入支持封面、截图和标题图的编辑器。 | 已加载的图片按原比例收边，保持完整画面；将 Tabler 图片编辑图标叠在实际封面右上角，保持底板对比度。按钮常显，悬停和键盘聚焦时提示「管理游戏图片」。无封面时显示「添加封面」，未配置目录时显示「指定图片目录」。已有 URL 加载失败时也应能进入替换流程。 |
| 编辑名称 | 铅笔已经位于标题行，但在截图中与短标题相隔整行。 | 将标题和铅笔组成相邻的一组。复用现有名称编辑器和「保存／取消」，打开即聚焦输入框，取消或按 Esc 后回到铅笔。 |
| 更多操作 | 菜单已经存在，位于关联文件和「更多信息」之后，默认向上展开。 | 把同一个菜单移到标题行右端，保留「更多操作」文字和下拉箭头，调整为向下展开、右边缘对齐。沿用「更新 ROM…」「恢复旧版 ROM」的现有可用条件。把「移出列表…」置末，与 ROM 操作分隔，继续打开移除预览。 |

## 第二批：让详情字段回答用户的问题

| 用户想知道什么 | 展示规则 |
| --- | --- |
| 这个游戏占多少空间？ | 主行使用「游戏占用」。复合游戏读取 `details.total_size`，单文件读取 `details.size`。示例主行显示「游戏占用　547.2 MB」。复合总量为空时显示「未能完整核对」，允许展开查看已知文件。 |
| 为什么 CUE 是 862 B？ | 用折叠的「文件明细」承载启动文件和关联文件：第一行列出 CUE 文件名和 862 B，再按 `details.files` 列出 BIN 等依赖及各自大小。总量已经包含启动文件，前端直接使用服务端总量。单文件游戏无需再展开一份重复明细。 |
| 用哪个核心启动？ | 当前明确配置与建议名称相同时合并成「运行核心　Beetle Saturn（推荐）」。两者不同则分行显示「当前核心」「建议核心」。当前值为 `DETECT` 时保留「由 RetroArch 选择」；如有推荐值，单列展示。 |
| 如何找到文件？ | 把「在游戏文件中查看」从页底移到启动路径旁，与复制按钮并列。复制仍取完整路径；路径较长时允许换行。定位继续受文件可读性及存储映射限制，原因在路径附近可见。 |

「更多信息」继续承载资料状态等只读信息；标题区的「更多操作」承载可执行命令。文件明细复用已有详情响应。[详情字段来源](../src/game_management.py) · [启动文件与依赖的大小计算](../src/disc_inspection.py)

## 验收清单

- **方形和竖版封面。** 对土星方形封面及一款竖版封面分别截图：画面完整，编辑按钮贴实际图片边缘。验证缺图、图片加载失败和未配置目录时的入口。
- **三个首击任务。** 从详情页开始，依次让首次使用者尝试「换图片」「改游戏名」「找到更新 ROM」。记录每次首次点击的控件。预期分别为封面按钮、标题铅笔、标题区的更多操作，三项均可在首屏找到。
- **键盘。** 使用 Tab 到达封面按钮、铅笔和菜单；打开菜单并执行或取消，检查焦点去向。用键盘从图片编辑器返回详情，确认触发控件可重新获得焦点。
- **文件与核心。** 覆盖 CUE＋BIN、依赖缺失及单文件三组数据。分别核对总量、明细、未知状态和定位按钮。核心覆盖相同、不同和自动选择三种情况。
- **尺寸与语言。** 在 1440 × 900、1100 × 700 下核对长标题、长路径和菜单边界；检查中英文及深浅主题。至少保留土星样例的详情首屏和菜单展开态两张图用于对照。

实施时更新[浏览器冒烟测试](../tests/browser_smoke.cjs)中固定要求「当前核心／建议核心／大小」同时存在的断言，改为按样例核对字段和值。继续覆盖现有名称编辑、图片编辑、ROM 预览与恢复流程。仓库根目录的针对性回归命令如下。
