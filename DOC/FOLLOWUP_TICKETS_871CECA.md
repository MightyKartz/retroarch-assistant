## R4-01 · 删除成功后回读失败，恢复的原镜像会被再次删除

**复现与影响**　在临时库中使用「继续清理」删除 CUE 和 BIN。让 CUE 的删除调用成功，再让紧随其后的回读抛出设备不可用错误。任务把磁盘上已不存在的 CUE 纳入新清单。将同内容的 CUE 从备份放回后，使用新标识继续，恢复的 CUE 被再次删除。上轮覆盖的“两个文件之间取消”场景已通过。

**实施建议**　在删除执行处保留已执行到哪一步的信息。对删除指令已发出、完成情况无法确认的文件，向界面返回路径和核对原因。后续清理标识只携带能确认尚未执行、且仍满足引用与指纹校验的文件。核对设备层删除后的内部回读和外层回读，两处都可能中断。[删除与回读](../src/chd_deploy.py) · [MTP 文件删除](../src/mtp_runtime.py) · [后续任务签发](../src/api_chd.py) · [部署窗口](../src/templates/chd-deployment.js)

**验收**

- [ ] 注入删除成功、随后回读失败，逐项核对磁盘、窗口和服务端新清单。窗口标明 CUE 待核对，新清单不包含该路径；仅剩待核对项时，界面不会显示清理已全部完成。
- [ ] 将相同字节的 CUE 放回原路径。旧标识被拒绝；如有其他待删项，使用新标识处理后，放回的 CUE 仍逐字节完整。
- [ ] 重跑文件间取消、正常完成和源内容或引用已变更的场景，既有继续清理能力与保护行为均通过。[CHD 回归测试](../tests/python/test_chd_deploy.py)

## R4-02 · 清理窗口依据错误文案判断任务标识是否有效

**复现与影响**　服务端明确返回「该清理任务已失效」时，窗口已能撤下按钮。但桌面请求层返回「连接已失效，请重新连接后重试。」时，同一段文案匹配也会清除任务标识。模拟提交后丢失响应，窗口提示结果未知，却立即重新启用携带旧标识的按钮。

**实施建议**　让 API 的明确拒绝具有可识别的错误类型，经请求层传给部署窗口。连接失效或响应丢失时保留用于核对的上下文；在确认原请求未执行且标识仍有效，或取得新的剩余清理标识后，再开放相应操作。[清理 API](../src/api_chd.py) · [桌面请求层](../src/templates/desktop.js) · [部署窗口](../src/templates/chd-deployment.js)

**验收**

- [ ] 服务端明确拒绝已消费或过期的标识，界面显示原因、撤下按钮并清除旧标识。
- [ ] 模拟连接失效及提交后丢失响应，分别验证前者不会误销毁有效任务上下文，后者不能在结果未确认时重复提交。
- [ ] 部分完成且返回新标识时，窗口显示实际剩余项；用户可以用新标识继续，完成后入口消失。[前端状态测试](../tests/chd_deployment_state.test.cjs)

## R4-03 · 首个列表前取消，批量进度分母沿用启动占位值

**复现与影响**　准备三个待处理列表，在第一个列表开始前取消。批量结果为 `processed_count=0`、`total_count=3`，任务终态却是 `progress=0`、`total=1`。历史显示 0/1，即时提示也未显示 0/3。已有测试在取消前手动把任务总数设为 3，未覆盖实际启动路径。

**实施建议**　批量执行结束时，将结果中的已处理列表数和列表总数一并写入任务终态，供即时提示和历史读取。游戏条目数继续使用自己的单位；其他任务继续使用各自的进度语义。[批量执行](../src/batch_review.py) · [任务管理](../src/job_manager.py) · [即时提示](../src/templates/tasks.js) · [补全历史](../src/templates/desktop.js)

**验收**

- [ ] 从正常任务入口启动三个列表，分别在首项前取消、完成一项后取消、全部完成。API、即时提示及重新打开的历史分别显示 0/3、1/3、3/3 个列表，终态分别为取消、取消、完成。
- [ ] 单个列表包含多个游戏时，条目数独立显示；原有取消结果中的部分写入信息及清理告警仍可查看。

## R4-04 · 关窗后的手动清理说明须保护共享 BIN

**复现与影响**　让两个 CUE 共用一个 BIN，只转换其中一张光盘。在清理阶段中断，此时列表已切到可用的 CHD，原 CUE 和 BIN 都在磁盘上。部署方案只允许清理被转换的 CUE，共享 BIN 属于保留项。按当前关窗说明，仅核对列表已切换和 CHD 可用，仍可能手动删除另一张光盘所需的 BIN。

**实施建议**　同步修订桌面指南的快速步骤、CHD 小节及部署说明。窗口仍打开时，引导使用经过校验的「继续清理」。关闭后，仅在能够核实文件属于原待删清单且当前无其他引用时，才指引手动清理。无法重建清单或确认引用关系时，明确指引保留文件。[桌面指南](DESKTOP_GUIDE.md) · [部署说明](CHD_DEPLOYMENT_AND_RECOVERY.md)

**验收**

- [ ] 用两个 CUE 共用 BIN 的样例逐步走查，按指南操作后，共享 BIN 和另一份 CUE 均完整可读。[共享音轨测试](../tests/python/test_chd_deploy.py)
- [ ] 分别验证窗口仍打开、已关闭且能确认待删范围、已关闭且不能确认范围三种情况，读者能判断应使用哪个入口、可处理哪些文件或应保留哪些文件。
