## R5-01 · 首次部署或继续清理回读失败后会重删已恢复的文件

**复现与影响**　有两条已复现的路径。首次部署时，CUE 已被删除，设备层抛出 `RemoveUnverified`；首次部署生成的后续清单仍含该 CUE。另一条路径发生在继续清理时：删除后的回读抛出 `ValueError`，异常离开执行器，API 重新挂回整份旧方案。两种情况下，将相同字节的 CUE 放回原路径再继续，恢复的文件都会被删除。

**涉及调用方与修复建议**　首次部署和继续清理应按同一规则记录每份文件的删除阶段。删除指令已经发出但无法核对结果时，将该路径列入待核对项，并排除在后续自动删除清单之外。API 处理异常时须保留已经发生的文件变动，只有确认本次执行尚未写入时才可恢复整份方案。[部署执行器](../src/chd_deploy.py) · [任务 API](../src/api_chd.py) · [文件校验](../src/chd_io.py) · [设备删除](../src/mtp_runtime.py)

**验收**

- [ ] 首次部署经公开 API 注入“删除 CUE 成功、设备回读失败”。任务结果列出 CUE 及待核对原因，后续标识的待删清单只含仍可确认的剩余项。
- [ ] 在继续清理入口注入删除后的回读 `ValueError`。旧标识不能再次执行整份方案；API 和界面均保留已发生的部分结果。
- [ ] 两条路径分别放回原字节的 CUE，再处理仍待删的 BIN。核对恢复的 CUE 字节完整、BIN 按预期清理；引用或指纹变化仍能阻止删除。

## R5-02 · 丢失提交响应后，窗口可能绑定其他游戏的清理标识

**复现与影响**　清理请求已送达服务端，但客户端没有收到新任务 ID。窗口先查上一次任务，再按标题查最近的清理任务。复验中，新标识已签发，界面却重新绑定了旧标识；另一组复验中，游戏 A 的核对响应在打开游戏 B 后返回，B 窗口显示了可点击的 A 清理按钮。

**涉及调用方与修复建议**　在提交之前建立可供服务端精确查询的请求标识，并将其与原清理任务绑定。返回结果时核对当前游戏记录和窗口版本。最近任务列表存在数量上限，列表为空、找不到匹配项或查询失败时，都应保留“结果待确认”状态。恢复连接后，应能从当前窗口再次核对。[窗口核对逻辑](../src/templates/chd-deployment.js) · [任务 API](../src/api_chd.py) · [最近任务快照](../src/job_manager.py)

**验收**

- [ ] 服务端接收请求后丢弃提交响应，同时保留多条同名任务。重新核对只命中本次请求；运行中不会重复提交，部分完成后只绑定其最新标识。
- [ ] 延迟 A 的核对响应，关闭 A 并打开 B，再返回 A 的结果。B 的按钮、明细和标识均不受影响。
- [ ] 将目标任务移出最近任务列表，再模拟一次断网。界面保持结果待确认，不能直接重提；恢复连接后能按原请求核对。服务端明确返回标识已失效时仍会撤下入口。

## R5-03 · 其他文件清理完成后，先前的待核对项从结果中消失

**复现与影响**　CUE 删除后回读失败，BIN 删除前失败。第一次继续清理正确区分了“CUE 待核对”和“BIN 待清理”。下一轮成功删除 BIN 后，返回 `completed` 和空的 `unverified`，窗口显示清理完成，用户失去了仍应核对 CUE 的提示。

**涉及调用方与修复建议**　在后续任务上下文中保留尚未核实的路径和原因。将本轮新增的待核对项与既有项合并，自动清理结束后继续展示这些项。该集合仅供核对，应与允许执行删除的清单分开保存。[结果与后续清单](../src/chd_deploy.py) · [任务上下文](../src/api_chd.py) · [结果展示](../src/templates/chd-deployment.js)

**验收**

- [ ] 用上述两份文件连续执行两轮。第二轮仅尝试删除 BIN，API 和界面仍列出 CUE 及原因，明确显示“自动清理已结束，仍有 1 项待核对”或等义提示。
- [ ] 连续多次中断时同一待核对路径只出现一次，后续标识不会把它转成待删项。所有文件均已核实时仍显示正常完成。

## R5-04 · 批量补全即时提示缺少列表进度

**复现与影响**　三份列表分别在首项前取消、首项后取消、全部完成。API 与历史已能显示 0/3、1/3、3/3；即时提示分别省略计数、只显示已处理 1 个列表、只显示已补全的游戏数。

**涉及调用方与修复建议**　批量应用结果存在时，即时提示从同一结果读取 `processed_count` 和 `total_count`。保留游戏条目数、残留告警和详情入口；分析阶段未产生应用结果时沿用现有提示。[即时提示](../src/templates/tasks.js) · [历史展示](../src/templates/desktop.js) · [任务计数](../src/job_manager.py)

**验收**

- [ ] 通过批量补全入口验证 0/3、1/3、3/3 三种结果，即时提示、API 与重新打开的历史使用相同的列表分子、分母及结束状态。
- [ ] 让一个列表包含多个游戏，核对两个计数各自标注“列表”和“游戏”；取消后仍可查看已产生的清理告警。

## R5-05 · 快速步骤与详细指南对关窗后手动清理的说明不一致

**复现与影响**　CHD 详细小节已说明共享 BIN 必须保留，快速步骤仍要求关窗后手动删除残留原镜像。详细小节还声称可从任务记录核对待删路径，当前 CHD 历史页只展示转换记录。只阅读快速步骤或关闭了窗口的用户容易把其他光盘仍需使用的 BIN 当成残留文件。

**涉及入口与修复建议**　统一快速步骤、CHD 详细小节和部署说明。窗口仍打开时使用经过校验的继续入口。关闭后，只处理可独立核实属于原待删清单、且当前无其他引用的文件；无法核实时明确保留。将查询说明限定为当前界面确实能展示的信息。[桌面指南](DESKTOP_GUIDE.md) · [部署说明](CHD_DEPLOYMENT_AND_RECOVERY.md) · [CHD 历史页](../src/templates/desktop.js)

**验收**

- [ ] 两份 CUE 共用一份 BIN，只转换其中一份。分别只读快速步骤、只读详细小节，两条路径都能得出“保留共享 BIN 和未转换 CUE”的结论。
- [ ] 关闭部署窗口，再按指南逐项走查。每个提到的入口均能找到所述信息；无法核实原待删清单时，读者得到明确的保留指引。
