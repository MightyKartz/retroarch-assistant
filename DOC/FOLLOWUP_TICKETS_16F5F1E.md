## R9-01 · MTP 对象 ID 和内容均变化时，应从待清理转为待核对

**优先级与状态**　P2，待修复。影响 CHD「继续清理」的任务结果和窗口操作。新文件受到保护，但任务反复签发无法完成的清理方案。

### 复现与证据

1. 在模拟 MTP 游戏库中预览并执行 CHD 替换，让原 BIN 删除失败，取得继续清理标识。
2. 在同一路径放入新 BIN，使设备对象 ID 和内容指纹均与获准删除的原 BIN 不同。记录新文件字节和此时的设备删除调用。
3. 点击「继续清理」，再用返回的新标识重试一次。实测两次均返回 1 项待清理、0 项待核对，并再次签发后续方案。新 BIN 字节完整，两次重试都没有新增设备删除调用。

### 原因与修复建议

MTP 删除入口先比较指纹。指纹变化会触发普通错误，使代码提前退出对象 ID 校验。上层据此把文件放入 `remaining`，而已确认被替换的对象应进入 `unverified`。[设备删除入口](../src/mtp_runtime.py) · [继续清理结果分类](../src/chd_deploy.py)

建议在持有获准对象 ID 时优先识别身份变化，复用已有的待核对结果传递路径和原因。对于身份匹配的对象，仍应在发出删除指令前完成现有指纹与对象身份校验。若还有其他可安全清理的文件，只为这些文件签发后续方案。[文件操作边界](../src/chd_io.py) · [清理 API](../src/api_chd.py)

### 验收

- [ ] 从公开部署 API 取得继续清理标识并复现上述替换。第一次继续后，结果中该路径只出现一次，归入 `unverified`，原因说明设备对象身份已变化；`remaining` 不含该路径。
- [ ] 若仅剩该 BIN，API 不再签发 `cleanup_id`，窗口显示待核对的路径和原因，撤下「继续清理」入口。核对新 BIN 的字节及设备删除记录，确认新对象完整、没有针对它的删除调用。[窗口展示](../src/templates/chd-deployment.js)
- [ ] 若另有可重试的原文件，使用后续标识执行第二次清理，确认只处理获准对象；被替换的 BIN 继续出现在待核对明细中。
- [ ] 对照验证原对象 ID、指纹和引用均未变化时仍可成功重试；原对象 ID 未变但内容已变化时，指纹校验仍会阻止删除。[MTP 测试](../tests/python/test_mtp_runtime.py) · [部署与继续清理测试](../tests/python/test_chd_deploy.py)
