## B-01 · 最终核对后更新的原件仍会被删除

**复现与影响**　使用实际 ExFAT 临时目录，预览替换 `Game/`，其中有 `old.bin`。在原目录移开之前打开 `old.bin` 的读写句柄并保持打开。等新件发布、已移开的原件通过最终摘要核对后，在真正调用清理前通过该句柄写入不同内容并刷新。已移开位置能读到新字节，但随后的删除会移除更新后的原件。任务报告替换成功，保留路径为空。[最终核对与清理](../src/game_file_actions.py)

**修复建议**　以清理期间能持续成立的条件决定是否删除用户原件。已有写入句柄在目录改名后仍然有效，增加一次摘要核对也会留下核对与删除之间的间隔。存储或操作无法可靠排除外部写入时，保留已移开的原件并报告真实路径。若新件已发布，应分别报告新件结果与原件保留状态。

- [ ] **用原句柄复验。** 注入点位于最后一次摘要核对返回后、清理开始前。用预先打开的真实文件句柄写入并刷新，核对更新字节仍能在结果给出的路径读取，原件未被报告为已清理。记录新件是否发布及其路径。
- [ ] **保留原始反例。** 继续验证等长、相同修改时间的复核期间改写，以及移开后、发布新件期间的修改。两种情况均保留新写入字节。
- [ ] **正常操作与回退。** 未变化的原件仍可按现有授权完成替换，结果明确说明原件是否保留。目标名被外部占用时，回退保住外部字节并报告实际可恢复位置。嵌套 MTP 替换和对象身份变化继续跑回归。

## A-02 · 完成的嵌套子目录未报告实际写入文件

**复现与影响**　在实际 ExFAT 上导入含 `Pack/A/a.bin`、`Pack/b.bin`、`Pack/c.bin` 的目录。让整个子目录 `A/` 发布成功，再在写入 `b.bin` 时注入 I/O 错误。目标中的 `A/a.bin` 字节完整，`written` 只返回 `Pack/A`。窗口因此只显示目录名。平铺的 `a.bin` 目前可以正确报告。[递归发布与结果汇总](../src/game_file_actions.py) · [窗口明细](../src/templates/game-files.js)

**修复建议**　递归发布无论成功返回还是中断，都把已经发布的实际文件路径交给上层。上层累计完成的子目录成员，并在随后的同名冲突或普通写入失败中原样返回。执行结果继续区分已写入文件、失败或待核对路径和未执行项。

- [ ] **完成子目录后失败。** 同一组样本中，API 的 `written` 和窗口明细都能查看 `A/a.bin`、实际目标和 `b.bin` 中断原因。确认 `c.bin` 没有计入写入结果。
- [ ] **子目录内部失败。** 同一任务先完成一个子目录，再在另一个子目录内部分写入后中断。已写入清单同时包含两处的实际文件路径，每条只出现一次。保留平铺失败、同名冲突和全部成功的回归。

## C-01 · 200 毫秒窗口内仍会借用旧来源

**复现与影响**　在 A 和 B 目录各放同名等长、内容不同的 `Game.sfc`。B 本次没有原生采集，队列只保留 100 毫秒前 A 的采集。将 B 的 DOM 事件交给实际配对函数，函数返回并消费 A 的路径。页面接到的回调仍携带 B 的落点事件时间。半秒前的记录已能拒绝，但配对规则仍不能证明命中的记录来自本次拖放。[原生事件配对](../src/desktop_window.py) · [页面落点校验](../src/templates/game-files.js)

**修复建议**　由原生侧与页面共享可核对的同一次拖放标识，或由同一可追踪事件交付可信来源与落点。时间、大小和文件名只用于辅助核对。缺少本次采集时提示使用「添加游戏」，保留其他事件的有效采集记录。

- [ ] **间隔与身份独立。** 用 100 毫秒和半秒两个间隔重跑缺采集场景。B 均无导入预览或写入，A 的记录未被错误消费。只有带本次关联依据的路径可进入预览。
- [ ] **多次拖放。** 两个有效拖放即使同名等长、回调逆序，也分别使用自己的源路径和落点，各提交一次。保留切换目录和旧页面回调的拦截。
- [ ] **实际 macOS 应用包。** 从 Finder 验证单文件、多文件和目录，覆盖不同目录的同名文件、字面量 `%20` 与文件夹落点。核对实际目标字节，验证来源缺失时能使用原生选择器完成导入。
