## R3-01 · CHD 继续清理中途取消会恢复整份旧清单

**复现与影响**　在临时游戏库生成包含 CUE、BIN 的待清理方案。调用「继续清理」，在 CUE 删除成功、开始处理 BIN 前取消。磁盘只剩 BIN，但 API 将原方案重新挂到旧任务标识。将相同内容的 CUE 从备份放回原路径，再用旧标识重试，恢复的 CUE 会再次被删除。

**涉及调用方与改法**　逐文件执行器在两项之间检查取消，此时可能已经完成删除。让执行器交回已删路径与剩余清单，API 消费已发生写入的旧方案，只为剩余项签发后续标识。部署窗口收到部分结果后应展示实际剩余项并绑定新标识，继续沿用引用和指纹校验。[清理执行](../src/chd_deploy.py) · [任务标识管理](../src/api_chd.py) · [部署窗口](../src/templates/chd-deployment.js)

**验收**

- [ ] 通过公开 API 重走上述流程。取消结果能说明 CUE 已删除、BIN 待处理，窗口和服务端的剩余清单一致。
- [ ] 放回原内容的 CUE，提交旧标识不会触发删除。随后从当前窗口用新标识完成清理，只删除 BIN，恢复的 CUE 字节完整。
- [ ] 正常完成后重复提交旧标识仍被拒绝；用户修改了待清理文件或新增了引用时，原有校验仍能阻止删除并说明原因。

## R3-02 · 替换目录时漏报旧目录清理失败

**复现与影响**　用新版目录替换含两个文件的同名目录。在新版发布成功后，让旧目录的第一个文件删除成功、第二个删除失败。旧目录以 `.plcn-old-*` 名称实际留在目标位置，但任务的 `leftovers` 为空，用户看不到残留位置。

**涉及调用方与改法**　普通删除在部分成功时返回带 `error` 的结果；替换流程仍仅在抛出异常时报告残留。发布成功后检查删除结果，将确实残留的旧目录路径传给现有任务摘要，同时保留新版发布成功的状态。[删除、替换与添加](../src/game_file_actions.py) · [文件管理结果摘要](../src/templates/game-files.js)

**验收**

- [ ] 注入第二项删除失败。核对新版目录内容正确，任务同时列出已替换项和残留旧目录；从界面给出的路径能找到未删文件。
- [ ] 清理全部成功时残留列表为空；旧目录第一项即删除失败时仍会报告残留路径。

## R3-03 · 清理标识已失效，界面仍允许重复点击

**复现与影响**　部署窗口使用旧标识请求继续清理，服务端明确返回「该清理任务已失效」。异常分支重新启用按钮并保留同一标识，用户再次点击会收到同样的错误。

**涉及调用方与改法**　让请求层与部署窗口能够识别服务端明确拒绝的标识，清空该标识并撤下按钮。若请求发出后结果未知，先核对任务状态或明确提示无法确认；收到有效的新标识时继续使用既有重试入口。与 R3-01 联调取消后的处理。[清理 API](../src/api_chd.py) · [桌面请求层](../src/templates/desktop.js) · [按钮状态](../src/templates/chd-deployment.js)

**验收**

- [ ] 模拟服务端明确返回失效，界面保留原因、清除旧标识，无法从该按钮重复提交。
- [ ] 模拟请求发出后丢失响应，界面说明结果待确认，不会直接拿旧标识再次提交。
- [ ] 连续两次部分完成后，只要返回有效后续标识，按钮仍可点击并使用最新标识；全部完成后入口消失。

## R3-04 · 批量取消后补全记录显示满进度

**涉及调用方与改法**　批量结果已提供 `processed_count` 与 `total_count`。让批量任务的 API 终态、即时提示、补全记录采用同一组列表计数。游戏条目数另有 `applied_count`，应标明单位。共享任务管理器还服务于文件删除等任务，须保留这些调用方返回的部分结果。[批量执行](../src/batch_review.py) · [任务终态](../src/job_manager.py) · [即时提示](../src/templates/tasks.js) · [补全记录](../src/templates/desktop.js)

**验收**

- [ ] 准备三个待处理列表，分别在首个列表前、首个列表完成后取消。API、提示和历史页分别显示已取消及 0/3、1/3 个列表，关闭提示后仍可核对。
- [ ] 三个列表全部完成时显示完成及 3/3；处理一个列表内多条游戏时，游戏条数不会被用作列表进度。
