## A-01 · 身份核对后换入的外部文件会被清理

**复现与影响**　使用实际 ExFAT 临时目录，将 `free.sfc` 导入空目标目录。使占位文件创建及写入完成后，在 `fsync` 注入错误以进入失败清理。让身份核对先正常完成，再在最终调用 `unlink` 之前用内容不同的外部文件替换占位文件。真实 `unlink` 会删除外部文件。当前回归在身份核对前换入文件，只验证了身份检查已能识别的分支。

**修复建议**　把清理限制在操作能够持续确认归属的对象上。平台没有可靠方式按已持有的对象身份删除时，可以保留失败路径并报告待核对。写入失败仍应返回真实原因和必要的残留信息。一次路径核对后再按路径删除，仍存在本工单的失败时序。[ExFAT 发布与失败清理](../src/game_file_actions.py)

- [ ] **最终清理注入点。** 用相同的测试钩子在身份核对完成之后换入外部文件。修复后核对外部文件仍存在且字节完整，任务失败结果与实际状态一致。
- [ ] **清理与保留。** 普通写入失败和刷新失败均没有复制成功记录。若留下路径，结果指出实际位置和核对原因。保留身份核对前换入、同名拒绝覆盖及正常复制的回归。

## B-01 · 复核期间或移开后更新的原件会被删除

**复现一**　在实际 ExFAT 临时目录中预览替换 `Game/`，目标有 `a.bin` 和 `b.bin`。执行复核已读取 `a.bin` 后，在计算 `b.bin` 摘要期间等长修改 `a.bin`，让修改时间仍和原值一致。若系统时间自然推进，测试钩子可恢复原修改时间以确保用例稳定。第二遍元数据检查仍匹配，结果报告替换成功，更新后的 `a.bin` 被删除。

**复现二**　同样预览整目录替换。让执行先把原件移到 `Game.plcn-old-*`，在发布新目录时修改已移开的原件中 `a.bin`，本用例可以改变文件长度和修改时间。当前实现直接清理已移开的目录，更新内容消失，任务报告替换成功。

**修复建议**　将删除授权落实到实际即将被清理的原对象及其内容。预览和逐成员复核形成的证据必须能证明它覆盖了准备删除的内容。某条路径无法取得一致证据时，保留有内容的原件，报告真实路径和原因。新件已经发布、原件仍保留时，结果必须表达这两个不同的事实。回退应继续采用无覆盖语义，保留之后出现的目标。[目标签名、替换发布与原件清理](../src/game_file_actions.py)

- [ ] **等长改写。** 复验第一个成员已取摘要后发生等长、同修改时间的改写。更新字节必须在报出的实际位置完整可读，结果不得声称原件已成功清理。
- [ ] **移开后更新。** 在原件移开后、清理前改写成员。新件若已发布，报告真实目标及原件的保留位置。没有发布时，不得误报成功。
- [ ] **正常与回退。** 证据完整且未变化的目录仍可替换。回退期间如有外部文件取得目标名，应保住外部文件并报告原件或新件的真实保留位置。保留嵌套 MTP 替换和成员身份变化的回归。

## A-02 · 普通子文件写入失败遗漏已经发布的路径

**复现与影响**　从实际 ExFAT 导入包含 `a.bin`、`b.bin` 的 `Pack/`。让 `a.bin` 发布成功，在 `b.bin` 写入时注入 I/O 错误。`a.bin` 留在目标，后台只返回 `Pack` 与错误，窗口缺少已写入路径和实际目标。现有明细仅在同名子项冲突等带有明细字段的结果上显示。

**修复建议**　让目录发布在各类中断中都保留此前已发布的成员。普通写入错误与已有的同名冲突可以复用同一份结果字段和窗口明细。区分已写入、保留的外部冲突或待核对残留、未执行项，并展示实际目标与中断原因。[发布结果](../src/game_file_actions.py) · [导入明细](../src/templates/game-files.js)

- [ ] 第一个成员发布成功、第二个成员写入失败，第三个成员未执行。后台与窗口均能查到 `a.bin`、真实目标和中断原因，实际输出与结果一致。
- [ ] 嵌套目录的部分结果能指出已发布的实际成员路径。保留现有同名冲突、全部成功及批量粘贴完整明细的回归。

## C-01 · 本次 Finder 采集缺失时仍可能消费半秒前的旧来源

**复现与影响**　在 A 与 B 目录各放一份 `Game.sfc`，文件同名、等长、内容不同。让 B 没有原生采集，队列仅保留半秒前 A 的记录。调用实际配对函数处理 B 的 DOM 事件。函数返回并消费 A 的路径，而回调会带着 B 的事件时间交给页面。当前新增测试只拒绝了一秒前的记录。

**修复建议**　使用原生采集与页面回调都能核对的同一次拖放标识，或把可信源路径和落点放进同一个可追踪事件流程。文件名、大小和时间可辅助检查，无法确认批次归属。无法关联本次采集时提示使用「添加游戏」，保留其他有效事件各自的记录。[原生拖放桥接](../src/desktop_window.py) · [落点校验](../src/templates/game-files.js)

- [ ] **窗口内旧记录。** 保留 A 半秒前的记录且 B 采集缺失。B 无导入预览和写入，A 的记录未被错误消费。改变时间间隔时，同一事件关联规则保持一致。
- [ ] **有效与无效事件。** 验证各有采集的两个快速拖放、回调反序、缺少采集和导航后迟到回调。有效批次各自只提交一次，使用自己的路径和落点。
- [ ] **实际应用包。** 从 Finder 实测单文件、多文件和文件夹，并用同名等长、内容不同的样本核对目标字节。保留中文、空格、字面量 `%20`、文件夹落点和原生文件选择入口的回归。
