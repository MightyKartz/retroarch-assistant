# beta2 桌面界面与 SVG 按钮优化实施计划

状态为待实施。基线为 `beta2`（`bcd0746`）。第一批建议交付主机页的补全操作区和详情页的就地操作，第二批调整 ROM 更新预览、通用确认框及历史记录按钮。

本计划负责入口、文案和交互反馈。自动改名、补图、人工处理数和数据源的业务规则见[补全与名称库修复计划](BETA2_REPAIR_PLAN.md)。两份改动相遇时，页面直接消费当前业务结果，避免在渲染函数内重新判断游戏能否补全。

## 按钮约定

| 场景 | 呈现方式 | 在本项目中的用法 |
| --- | --- | --- |
| 常见工具，操作对象已在旁边 | 纯 SVG，低强调 | 标题旁的编辑、路径旁的复制、设置、关闭 |
| 两个互斥视图 | 一组相连的 SVG 按钮 | 封面／列表，共享选择状态，当前项有选中样式和 `aria-pressed` |
| 主要操作，效果取决于对象或数量 | 可见的动词和对象 | 「补全当前列表」「补全所选 3 项」 |
| 写入、恢复、移出等操作 | 菜单项和最终确认保留文字 | 「替换 ROM」「恢复旧版 ROM」「移出列表…」 |

沿用现有 Tabler 线性图标、24 单位网格和项目的 1.7 线宽。桌面工具按钮以现有的 36 × 36 px 点击区、20 px 图标为基准。行内按钮可在视觉上减弱边框，并保留足够的点击区和清晰的键盘焦点。新增 `copy` 等图形时补入共享 sprite，静态模板走 `data-ui-icon`，动态按钮复用已有渲染入口。预览搜索框中的字符 `⌕` 改用已有的 `search` 图标，并作为装饰从读屏顺序中排除。[图标库](../src/templates/workbench-icons.svg) · [图标按钮实现](../src/templates/workbench.js) · [样式](../src/templates/workbench.css)

纯图标操作使用原生 `button`，提供中英文可访问名称。鼠标悬停和键盘聚焦时均可查看用途；提示不能遮挡相邻操作。弹层关闭后焦点回到触发按钮。主要操作的范围和写入后果直接出现在可见文字中。

## 第一批：游戏库与详情页

### 1．合并主机页的补全操作区

目前勾选一款游戏后，`game-selection-toolbar` 与 `games-status` 可同时显示「补全」和「一键补全」。两个按钮分别作用于选中项和整个列表。建议共用同一个布局位置，并按以下状态渲染。

| 状态 | 内容与操作 |
| --- | --- |
| 未选择，有图片待补全 | 显示「N 款游戏的图片待补全」及「补全当前列表」。按钮作用域仍是当前完整列表，包括当前搜索范围之外的条目。 |
| 未选择，无图片待补全 | 收起图片提示，保留现有适用的名称补全入口。 |
| 已选 N 项 | 显示选择当前可见项的复选框、已选数量、主按钮「补全所选 N 项」、「更多操作」和清除选择按钮。将「移出列表…」放到更多操作中。 |
| 清除选择／任务进行中 | 清除后立即恢复未选择状态；任务期间沿用写入锁及当前任务反馈。 |

单项切换只调用 `renderGameSelection`，完整刷新还会调用 `renderGameLibrary`。两条路径都要更新同一操作区，尤其要覆盖勾选第一项和取消最后一项。表头复选框沿用当前已呈现条目的范围，含筛选和显示条数上限；按钮提示应明确「选择当前显示的游戏」。批量补全仍传已选条目的索引和 ROM 路径。右上角「游戏文件」调整为次要工具样式，封面／列表开关做成分段控件。[模板](../src/templates/plcn.html) · [列表与筛选](../src/templates/library.js) · [选择工具栏](../src/templates/game-management.js)

### 2．把详情操作移到对应内容旁

| 位置 | 改动 | 验收要点 |
| --- | --- | --- |
| 游戏标题 | 铅笔按钮打开现有名称编辑器 | 输入框获得焦点，保存和取消均有可见文字；取消后回到编辑按钮。 |
| 封面 | 无封面时在占位区显示「添加封面」；已有封面时提供角落的更换按钮 | 鼠标和键盘都能进入现有封面编辑器；未配置目录时仍能「指定图片目录」。 |
| 启动路径 | 路径末尾使用复制图标 | 复制成功短暂显示对勾并播报「已复制启动路径」；失败时保留可选中的原路径并提示原因。 |
| 文件操作 | 把「更新 ROM…」「恢复旧版 ROM」「移出列表…」收进带文字的「更多操作」 | 按原条件决定可用性；无法定位文件时，在路径附近解释原因。「移出列表…」仍打开已有预览，显示实际影响条目。 |

详情页现有的「更多信息」用于展开资料字段，与「更多操作」分别命名。移动按钮时保留控件 ID、忙碌状态和返回焦点；从详情页返回时仍回到先前浏览的游戏。[详情页与 ROM 更新入口](../src/templates/game-browser.js)

## 第二批：写入确认与通用按钮

### 3．收拢 ROM 更新预览

从「更多操作 → 更新 ROM…」选择文件后，页面只展示一组预览操作。预览保留新文件名、原大小与新大小、备份说明，底部主按钮写「替换 ROM」，次按钮写「取消」。取消后回到可再次选择文件的状态，执行仍复用已有预览计划和任务锁。验收时分别完成一次取消和一次替换，核对取消未写入、确认只提交一次、成功后能找到「恢复旧版 ROM」。

### 4．修正通用按钮的默认历史图标

`desktopButton` 当前默认使用 `history`，并把传入文字替换成 SVG。先核对其调用点：无显式图标时保留文字；历史记录入口可显式使用历史图标，记录内的「重试未完成图片」「撤销」「恢复此次列表修改」保留具体动词。通用确认框目前显式传入叉号和对勾，因此也要单独调整，按当前操作显示「取消」和具体确认文案。沿用原有点击处理、禁用和错误反馈。[桌面按钮与确认框](../src/templates/desktop.js)

## 回归与交付

| 用例 | 通过条件 |
| --- | --- |
| 主机页依次选择 0 → 1 → 多项 → 0 | 搜索栏下始终只有一个生效的操作区；补全按钮的数量与实际提交范围一致。 |
| 切换视图、筛选、显示更多 | 已选项在两种视图间保持一致。全选只影响当前显示项，清除选择清空全部已选项。 |
| 图片只有截图缺失 | 主机页采用「图片待补全」文案，详情能指出具体缺项。总览「缺少封面」按盒封口径验收。 |
| 键盘操作与反馈 | Tab 可达新控件；按钮支持 Enter／空格；关闭菜单或取消编辑后焦点可预测；复制反馈可由读屏工具读取。 |
| 浅色／深色、中文／英文、1440 × 900／1100 × 700 | 工具栏数量与操作范围可见，菜单和确认按钮不被裁切。长游戏名和长路径不挤掉关联按钮。 |
