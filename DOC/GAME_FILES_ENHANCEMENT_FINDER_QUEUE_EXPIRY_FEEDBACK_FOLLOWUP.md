# C-03m 游戏文件导航失败后批次失效提示丢失修复工单

**优先级 P2**　两批文件已匹配时，如果第一批写入后的旧刷新先返回，第二批的落点失效提示会在随后的导航失败时消失。审查基线为 `b3b00c2` 上含 C-03l 实现的工作区，`game-files.js` 的 SHA-256 前缀为 `113c24f2f547`。C-03l 的原始顺序已通过，本工单补齐反向顺序。[上一轮工单](GAME_FILES_ENHANCEMENT_FINDER_QUEUE_NAVIGATION_ERROR_FOLLOWUP.md)

## 复现与影响

1. 在临时目录 `/Roms/A` 匹配两批内容不同的文件。让第一批完成真实写入，暂缓写入后发出的 `/Roms/A` 刷新响应。
2. 用户通过目录行进入 `/Roms/A/B`，暂缓新目录响应。先释放旧刷新，等队列将第二批判定为过期并出队，页面此时显示「放置位置已失效，请重新拖入」。
3. 让新目录读取失败，例如返回 `folder B unreadable`。等所有回调结束后检查状态栏、可展开的操作详情和两个目标文件。

最终状态栏显示目录错误，操作详情只保留第一批的已复制摘要，第二批的失效原因消失。隔离 Chromium 复验在「导航失败后失效提示仍可见」的断言处失败，同时核对了第一批字节正确和第二批目标文件不存在。[失效提示](../src/templates/game-files.js#L802) · [写入结果延后呈现](../src/templates/game-files.js#L816) · [导航失败处理](../src/templates/game-files.js#L988)

## 修复建议

将导航等待期间产生的批次失效提示保留到该导航结算。新目录读取失败后，让状态栏继续显示具体错误，并在可查的结果区域保留第一批写入结果和第二批失效反馈。沿用现有的视图与导航归属校验，避免提示随后续无关导航重播。保持队列在落点失效时正常出队。[批次出队](../src/templates/game-files.js#L503) · [操作详情](../src/templates/game-files.js#L765)

## 验收条件

- [ ] **旧刷新先返回。** 用显式等待点确认第二批已在导航等待期间出队，再令导航失败。所有回调结算后，具体读取错误、第一批写入摘要及明细、第二批落点失效反馈均可查。
- [ ] **新导航先失败。** 保留 C-03l 的原始回归。先等待具体读取错误出现，再释放旧刷新，最终同样能查看上述三项信息。[原始顺序浏览器回归](../tests/browser_smoke.cjs#L1532)
- [ ] **磁盘与恢复。** 两种顺序均断言只提交第一批，核对其目标字节和第二批目标文件不存在。恢复读取并返回目录后，列表能看到已写入文件，写入次数保持为一，旧提示没有在无关导航上重播。
- [ ] **既有行为。** 复验 C-03k 的单批两种返回顺序、正常目录读取时的批次失效提示，以及同目录或兄弟目录中有效批次的串行写入。[单批回归](../tests/browser_smoke.cjs#L1477) · [连续批次回归](../tests/browser_smoke.cjs#L745)
