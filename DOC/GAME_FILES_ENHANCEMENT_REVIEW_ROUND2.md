## GF-04-R1 · 无覆盖发布仍会覆盖新目标

**复现与影响**　仓库所在 ExFAT 卷的硬链接调用实测返回「Operation not supported」。用测试钩子在最后一次目标存在性检查后、实际系统 `rename` 前创建同名文件。任务报告复制成功，目标字节由外部文件变成导入文件。本地目录分支同样会替换在该时刻出现的空目录。首轮测试在暂存写入阶段创建冲突，覆盖了检查之前出现目标的情形。

**修复建议**　让最终发布操作本身具备拒绝已有目标的语义。硬链接不可用时，根据平台使用具备该语义的发布方式。无法保证时保留现有对象并报告原因。遇到冲突只清理本任务创建的暂存内容。保持普通无冲突导入和单独授权的替换流程。[发布实现](../src/game_file_actions.py)

- [ ] 用当前 macOS 和实际 ExFAT 测试目录复验，在最终发布时插入同名文件。外部内容逐字节保留，结果报告冲突，复制成功与替换计数均为零。
- [ ] 在最终发布前插入同名空目录，目录保持原样，导入内容未写入其中。保留原有测试中的提前冲突、普通复制和授权替换用例。

## GF-04-R2 · MTP 目录替换仍会删除已变更的成员

**复现与影响**　模拟 MTP 设备对 `Game/keep.bin` 返回空修改时间。预览后将该成员换成同名、等长、内容不同并拥有新对象 ID 的文件。目录校验值保持相同。通过实际替换流程执行，任务报告替换成功，新文件被清理。

**修复建议**　在 MTP 目录校验中纳入成员对象身份，并在发布前复核。遇到设备缺少足以判断内容变化的元数据时，取得可靠依据后再执行替换，或保留目标并报告无法核对。继续沿用本地目录的成员变更回归。[MTP 枚举与目录替换](../src/game_file_actions.py) · [MTP 元数据](../src/mtp_runtime.py)

- [ ] 重跑同名、等长、修改时间未知且对象 ID 改变的复现。更新后的成员和原目录仍存在，结果报告目标变化或无法核对，替换计数为零。
- [ ] 覆盖对象 ID 未变、内容有变化但缺少修改时间的情况。没有可靠依据时保留目标。可以完整核对且未变化的目录继续按批准执行。

## GF-05-R1 · 原生回调乱序会交换两次拖入的来源

**复现与影响**　按顺序捕获原生拖放 A 与 B，再按 B、A 顺序调用实际 DOM 回调。B 的回调取走 A 的 URL，A 再取到 B 的 URL。两批各有一个文件，数量相同的配对分支直接接受，甚至文件名不同也会交换。单次 URL 解码已通过字面量 `%20` 的检查。

**修复建议**　以本次拖放的标识将原生 URL 与 DOM 事件关联。只有能确认属于同一事件时才传给前端。无法关联则提示使用「添加游戏」，保留原生 URL 只解码一次的行为。可与 GF-05-R2 共用事件标识及回归环境。[原生拖放桥接](../src/desktop_window.py)

- [ ] 模拟不同时序的两次拖放，包含回调乱序与其中一个事件缺失。每个已接收事件只使用自己的路径，无法确认来源时不提交导入。
- [ ] 用 macOS 应用包从 Finder 核对中文、空格、字面量 `%20`、文件夹及不同目录的同名文件。核对实际目标字节。

## GF-05-R2 · 迟到的旧回调仍能借用新落点

**复现与影响**　在 A 放下第一批文件，暂缓其原生回调。导航到 B，放下第二批，再送达第一批回调。实际前端处理函数把第一批路径提交给 B，并清除第二批落点。目录加载期间直接拖入已能拦截。

**修复建议**　落点和路径回调均绑定同一次拖放。前端核对拖放标识、页面和导航版本，然后只消费该事件的落点。旧回调应及时丢弃，且不能清除后续有效落点。[落点与导航逻辑](../src/templates/game-files.js)

- [ ] 固定上述交错顺序，第一批回调没有触发预览，也没有清除第二批落点。第二批回调只为自己的源路径和 B 发出一次预览请求。
- [ ] 保留目录加载中禁收拖入的验收，并验证关闭后重新打开文件页时，前一页面的回调不会作用于新页面。

## GF-03-R2 · 部分复制的窗口结果缺少文件明细

**复现与影响**　模拟 MTP 目录第一份 BIN 写入成功、第二份断连。后端已经返回 `target`、`written` 与 `error`，实际窗口汇总只显示目标目录和写入项数。用户无法从结果判断具体写入了哪份文件，也看不到断连原因。

**修复建议**　在部分完成结果中使用现有后端字段展示目标路径、已确认写入文件的路径与中断原因。保留完整成功、高亮及后续未执行项的反馈。[粘贴结果展示](../src/templates/game-files.js) · [批量复制结果](../src/game_file_actions.py)

- [ ] 提供部分完成结果的窗口回归。用户可在界面查到实际写入的 `a.bin`、真实目标路径及断连原因。取消时展示取消状态与已确认写入范围。

## GF-03-R3 · 单项 MTP 复制取消被报告为失败

**复现与影响**　通过 `/api/game-files/file-ops` 的单路径请求发起 MTP 复制，在传输时抛出 `TaskCancelled`。实际任务以 `failed` 结束。共享复制实现将其包装成 `CopyPartial`，批量入口检查包装后的取消标记，旧单项入口由任务管理器直接按异常类型判断。

**修复建议**　在共享实现或单项调用边界保留单项原有的取消语义，同时让批量调用仍能获取部分写入明细。[单项与批量 API](../src/api_library.py) · [MTP 复制](../src/game_file_actions.py) · [任务状态](../src/job_manager.py)

- [ ] 使用原单项请求中的 `path` 参数启动任务，传输中取消后状态为 `cancelled`。真实传输异常仍报告失败。
- [ ] 使用批量 `paths` 请求在目录部分写入后取消，状态和已写入明细仍正确。
