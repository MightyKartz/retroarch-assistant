# C-03j 游戏文件写入后目录刷新错误修复工单

**优先级 P2**　导入、粘贴或删除完成后，目录刷新失败时，任务摘要会覆盖读取错误。审查基线为 `b3b00c2` 上含 C-03h 和 C-03i 修复的工作区，`game-files.js` 的 SHA-256 前缀为 `a5460c9e6f69`。C-03h 的延迟补刷和 C-03i 的预览回归均已通过，本工单覆盖用户留在原目录时的普通刷新。[上一轮工单](GAME_FILES_ENHANCEMENT_FINDER_QUEUE_REPLAY_FOLLOWUP.md)

## 复现与影响

1. 打开临时游戏目录 `/Roms/A`，导入一个无冲突文件。保持页面在原目录。
2. 让写入任务正常成功。仅让任务完成后紧接着发出的目录读取失败，例如返回 `disk gone`。
3. 等待目录请求和写入完成回调全部结束，再检查列表、状态栏与操作明细。

实际前端时序为「正在复制」→「正在读取目录」→「读取目录失败」→「已复制」。目录读取将列表清空并返回 `failed`，导入调用方随即写入成功摘要，用户无法从最终状态判断列表读取失败。该时序已通过实际前端函数和受控任务响应复现。粘贴与删除的完成回调也无条件写回任务摘要。[目录读取失败处理](../src/templates/game-files.js#L943) · [导入完成回调](../src/templates/game-files.js#L1147) · [粘贴完成回调](../src/templates/game-files.js#L811) · [删除完成回调](../src/templates/game-files.js#L716)

## 修复建议

普通刷新调用方应使用现有的目录刷新结果，确保仍有效的读取错误保持可见，并让用户仍能查看本次写入摘要和相关明细，例如已写入的路径、保留路径或中断信息。可集中处理导入、粘贴和删除的结果呈现，沿用 C-03h 对过期刷新和新任务结果的校验。核对共用刷新入口的重命名调用，保持其原有交互。若用户重新读取目录，应只发起读取请求，避免重复提交已经完成的写入。[共用刷新入口](../src/templates/game-files.js#L493) · [延迟补刷校验](../src/templates/game-files.js#L922) · [重命名调用](../src/templates/game-files.js#L612)

## 验收条件

- [ ] **导入。** 在临时目录完成真实写入，仅让随后发出的目录读取失败。全部回调落定后，具体读取错误仍可见，导入结果可查，文件字节与来源一致，导入只提交一次。
- [ ] **粘贴与删除。** 分别从各自入口执行操作，在写入响应结束后拦截目录读取并令其失败。确认具体读取错误仍可见，任务结果与实际文件状态一致，各提交一次。用含已写入路径的部分粘贴结果复验，操作明细仍可查。
- [ ] **恢复与回归。** 恢复目录读取后刷新页面列表，列表反映已完成的写入，请求记录无重复的文件操作。复验正常刷新成功、C-03h 的过期与失败补刷、C-03g 的第五条保留路径，以及 C-03i 的同名预览回归。
