# C-03k 游戏文件刷新与导航失败交错修复工单

**优先级 P2**　写入后的目录刷新与用户导航同时在途时，导航失败会导致读取错误被覆盖，或让已完成的写入结果停留在待恢复状态。审查基线为 `b3b00c2` 上包含 C-03j 实现的工作区，`game-files.js` 的 SHA-256 前缀为 `a875935d213e`。C-03j 的导入、粘贴和删除普通刷新失败场景均已通过。[上一轮工单](GAME_FILES_ENHANCEMENT_WRITE_REFRESH_FAILURE_FOLLOWUP.md)

## 复现与影响

1. 打开临时目录 `/Roms/A`，完成一次导入。暂缓写入成功后紧接着发出的 `/Roms/A` 目录刷新响应。
2. 通过目录行或面包屑发起导航，例如进入 `/Roms/A/B`。让新目录读取以可识别的错误失败，如 `folder B unreadable`。
3. 按下列两种顺序分别交付响应，每次从独立的初始状态开始。两种现象均通过实际前端函数和受控响应复现。

| 响应顺序 | 当前表现 |
| --- | --- |
| 新导航先失败，旧刷新随后成功返回 | 旧刷新已被识别为 `stale`，但此时 `navInFlight` 已为假。`presentWriteResult` 写回「已复制」，覆盖新目录的读取错误，列表仍为空。 |
| 旧刷新先成功返回，新导航随后失败 | 写入结果进入待恢复状态。导航失败分支保留读取错误，但未呈现已完成的写入摘要和明细。 |

两种顺序下，用户都应看到新目录的具体读取错误，并能展开查看已完成写入的摘要和相关路径。[写入结果呈现](../src/templates/game-files.js#L799) · [过期刷新判定](../src/templates/game-files.js#L885) · [待恢复结果与导航失败](../src/templates/game-files.js#L939)

## 修复建议

让结果呈现同时遵循目录请求和写入任务的归属。旧刷新返回 `stale` 时，先判断最新导航的读取状态，再决定如何显示写入结果。导航失败时，应结算由该导航等待的写入结果，将仍相关的摘要和明细放进已有详情区域，让状态栏保留具体读取错误。已经结算的待恢复结果应及时清理，避免后续导航再次应用。复用 C-03j 的结果详情和 C-03h 的版本校验，覆盖共用入口中的导入、粘贴和删除。[共用刷新入口](../src/templates/game-files.js#L493) · [操作明细](../src/templates/game-files.js#L761)

## 验收条件

- [ ] **新导航先失败。** 确认状态栏已显示 `/Roms/A/B` 的读取错误，再释放 `/Roms/A` 的旧刷新。全部回调结束后，仍显示同一读取错误，展开详情可见本次写入摘要和相关路径，旧目录响应没有替换目录列表。
- [ ] **旧刷新先返回。** 确认新导航仍在等待时释放旧刷新，再让新目录读取失败。最终仍同时保留具体读取错误和可展开的写入结果。下一次成功导航后检查，先前待恢复的结果没有被重复呈现。
- [ ] **写入与恢复。** 用临时目录核对至少一次真实导入的目标字节。两种顺序均断言文件操作只提交一次。目录恢复读取后，列表反映已经完成的操作，无重复写入。
- [ ] **既有场景。** 复验 C-03j 的普通刷新失败、C-03h 的过期及失败补刷、C-03d 的成功导航和 C-03g 的完整明细。继续覆盖正常导入、粘贴和删除。[延迟补刷回归](../tests/browser_smoke.cjs#L1191) · [普通刷新回归](../tests/browser_smoke.cjs#L1311)
