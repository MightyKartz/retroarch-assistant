## C-03 · 两批来源均已匹配时，仍会静默漏写一批

**优先级**　P2，待修复。

**复现与影响**　让 A、B 分别落在两个有效目录，逆序回传各自的 nonce 和源路径。两批均发起无冲突预览。在 B 的预览返回并开始写入后，保持其任务未结束，再返回 A 的预览。A 随后调用 `submitAdd`，因 `changing` 已为真直接退出。实际前端函数记录两次预览、一次写入，A 没有结果或提示。现有浏览器回归先关闭第一批冲突预览，再发送第二批回调，未覆盖两批同时在途。[预览与写入入口](../src/templates/game-files.js) · [现有逆序用例](../tests/browser_smoke.cjs)

**修复建议**　来源与落点匹配成功后保存该批次，依序处理预览、冲突确认及写入。按批保留原始目标和导航上下文。前一批结束时推进下一批，用户主动导航、关闭页面或目标失效时反馈受影响的批次。区分任务结束后的同目录刷新与用户切换目录，确保正常刷新后仍可执行有效的后续批次。

- [ ] **两批无冲突且同时在途。** 在第一批写入尚未结束时返回另一批预览。待任务结束后，两批均恰好写入一次，实际源路径、目标目录和文件字节各自正确，无静默漏写。若实现选择串行预览，可用同样的异步控制确认第二批等待至可执行。
- [ ] **冲突确认与取消。** 第一批等待用户确认时送达第二批。关闭或取消第一批后，第二批仍能继续；确认第一批时，第二批在该次写入完成后继续。每批都有自己的执行结果。
- [ ] **关联与导航。** 覆盖来源先到、落点先到、逆序回传及同一 nonce 重复回传。有效批次只执行一次。切换目录或关闭重开后，失效批次没有写入其他目录，正常同目录刷新不会丢失仍有效的批次。

## Finder 打包验收

**待确认的边界**　浏览器回归人为注入了 `org.plcn.dropid`。本轮检查了 AppKit 的异步调用，但尚未完成跨窗口真实 Finder 拖放。上游 WebKit 的 macOS 实现会筛选可暴露给 DOM 的原生剪贴板类型，需在本机应用包中核对，才能确认当前写入的自定义标识是否能由页面读取。[WebKit macOS 剪贴板实现](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/platform/mac/PlatformPasteboardMac.mm#L1959-L2029) · [原生采集](../src/desktop_window.py)

- [ ] **实际应用包。** 从 Finder 拖入单文件、多文件和目录。记录原生采集、DOM 可读关联、实际落点与目标字节。覆盖同名等长但内容不同的来源、字面量 `%20`、文件夹落点和连续两批。界面保持响应，每个有效批次按正确来源和落点完成。
- [ ] **关联缺失。** 复验无法取得本次关联标识的拖放。没有导入预览或写入，页面提示使用「添加游戏」。用原生选择器可完成同一批文件的等效导入。
