## FIX-01 · 成功执行后使旧清理任务失效

**复现与影响**　在临时游戏库中使 CHD 部署在切换引用后中断，用返回的任务标识继续清理至成功。将相同内容的原镜像从备份放回原路径，再提交旧任务标识，两份刚放回的文件被再次删除。

**实施建议**　服务端在启动清理时原子占用对应方案，成功时终结该方案，部分成功时只为已核实的剩余项签发后续标识。区分请求未启动与任务已执行，确保可恢复的中断有明确的继续入口。保留现有引用范围和文件指纹检查。[部署 API](../src/api_chd.py) · [清理执行](../src/chd_deploy.py)

- [ ] 在临时库通过公开 API 重走上述流程，重提旧标识不会启动第二次删除，放回的两份文件内容完整。
- [ ] 同一标识重复提交时仅一个任务取得执行权。部分完成后的新标识可继续，前一标识无法再次执行原清单。

## FIX-02 · 按实际删除结果生成 CHD 剩余清单

**复现与影响**　让 CUE 删除成功、BIN 删除失败，磁盘只剩 BIN，返回的待清理清单却包含二者。执行时在源文件副本上记录删除状态，生成清单时读取了另一份独立副本。[部署执行与结果生成](../src/chd_deploy.py)

**实施建议**　按实际成功删除的路径生成一份剩余集合，供界面展示与服务端继续清理共同使用。

- [ ] 注入第二个文件删除失败，逐项核对磁盘、公开结果和服务端待办，三者都只含 BIN。
- [ ] 用后续标识继续，执行器只尝试处理 BIN。完成后待办为空，已验证的 CHD 与列表引用保持正确。

## FIX-03 · 继续清理再次中断后恢复按钮

**复现与影响**　第一次中断后点击「继续清理」，第二次仍返回部分完成。界面收到新任务标识并显示按钮，但按钮仍为禁用状态。请求报错分支也只恢复了可见性。[部署窗口](../src/templates/chd-deployment.js)

**实施建议**　让按钮的可见性、可用性和任务标识随同一结果更新。请求异常时区分可安全重试和任务状态待确认，避免重新启用已消费的标识。与 FIX-01 联调。

- [ ] 连续两次中断后，当前窗口的按钮可点击，第三次请求使用最新标识，完成后入口消失。
- [ ] 覆盖未成功发起请求、部分完成、全部完成和切换记录四条路径，界面均能说明可采取的下一步，切换记录后不会出现前一个游戏的按钮。

## FIX-04 · 目录删除失败时同步已删除文件

**复现与影响**　临时目录有三个文件。删除第一个后，让删除第二个文件时抛出权限错误。磁盘剩余两个文件，任务只返回错误，界面无法登记首个文件的变动。主动取消已有部分结果处理，可复用其登记流程。[删除执行](../src/game_file_actions.py) · [任务 API](../src/api_library.py) · [同步登记](../src/templates/game-files.js)

**实施建议**　区分完整删除、主动取消和 I/O 失败。已有删除成功时返回已删路径、失败位置及原因，刷新目录并仅为已确认删除的文件登记同步。

- [ ] 注入第二项失败，界面显示已删数量和失败原因；应用列表同步后只移除第一项，剩余两个文件和对应条目均在。
- [ ] 第一项即失败时没有待同步删除；主动取消及完整目录删除沿用各自已验证的结果。

## FIX-05 · 统一批量取消的终态和计数

**复现与影响**　在首个列表处理前取消，任务状态为 `completed`，结果却是 `cancelled=true`、`processed_count=0`。即时提示显示已取消，进入「补全记录」则显示完成。[批量执行](../src/batch_review.py) · [任务管理](../src/job_manager.py) · [进度监听与即时提示](../src/templates/tasks.js) · [补全记录](../src/templates/desktop.js)

**实施建议**　从实际停止原因生成一致的任务终态，同时保留部分结果。如果调整共享任务状态，进度监听器也要能在取消时取得已处理数量和告警。

- [ ] 分别在首个列表前、一个列表完成后取消；API、即时提示和历史均显示取消，实际完成数分别为 0、1，磁盘写入与计数一致。
- [ ] 普通完成及全部写入后才收到取消请求均显示成功，已有部分删除结果仍能送达文件管理界面。

## FIX-06 · 隔离单个 MTP 播放列表的读取错误

**复现与影响**　模拟两份列表，第一份可读且有匹配项，第二份读取时抛出 MTP 传输层实际使用的 `RuntimeError`。整次预览退出，健康列表的变更无法应用。[设备读取](../src/mtp_runtime.py) · [同步预览与写回](../src/game_file_sync.py)

**实施建议**　在单个列表的设备读取边界记录失败文件及原因，继续处理其他列表。写回前仍需校验健康列表的预览快照。

- [ ] 单份失败时预览列出失败原因，并可更新健康列表；失败列表无写入请求。
- [ ] 所有列表均读取失败时显示全失败并禁用应用；现有损坏 JSON 和混合库零匹配测试继续通过。

## FIX-07 · 批量取消后显示并保留 MTP 残留告警

**复现与影响**　第一个列表已成功写入但留下旧对象，后续取消批量任务。结果已包含 `cleanup_warnings`，取消提示和「任务明细」均未呈现残留路径。[批量结果](../src/batch_review.py) · [即时提示](../src/templates/tasks.js) · [任务明细](../src/templates/desktop.js)

**实施建议**　取消提示说明已完成部分存在残留，在可重新打开的任务明细中列出具体路径。与 FIX-05 共用实际返回的部分结果。

- [ ] 模拟先产生列表和图片两类残留，再取消后续处理；提示可进入明细，关闭提示后从补全记录仍可找到两类路径。
- [ ] 核对新对象内容正确，没有重复发布；无告警时不出现残留提示。
