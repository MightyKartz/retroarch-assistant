## R6-01 · MTP 删除返回非零错误码后，重试可能删除已恢复的 CUE

**复现与影响**　在模拟设备中保留项目现有的 MTP 删除处理逻辑，让底层删除 CUE 后返回非零错误码。首次部署将该路径加入待删清单。将相同字节的 CUE 从备份放回原路径，再继续清理，恢复的文件被删除。

**涉及调用方与修复建议**　MTP 删除调用当前把非零返回值转为普通运行错误。保留删除指令是否已发出的信息；如果指令已发出、其结果无法确认，就向部署执行器返回待核对的路径和原因。首次部署与继续清理都应将该路径排除在后续自动删除清单之外。删除前确认未执行的失败继续沿用现有恢复流程。[设备删除](../src/mtp_runtime.py) · [文件操作边界](../src/chd_io.py) · [清理执行](../src/chd_deploy.py) · [后续任务签发](../src/api_chd.py)

**验收**

- [ ] 分别从首次部署和继续清理入口注入“设备已删除、底层返回非零”。API 与窗口均列出 CUE 待核对及原因，后续待删清单中没有该路径。
- [ ] 放回同内容的 CUE，使用后续标识处理可确认的剩余项，核对 CUE 字节完整且没有第二次针对它的删除调用。
- [ ] 在删除指令发出前注入失败，核对任务仍准确说明失败位置；正常成功路径及引用、指纹检查继续通过。

## R6-02 · 待核对的 CUE 缺席时，目录校验会阻断剩余 BIN 的清理

**复现与影响**　让 CUE 删除后的核对失败，同时让 BIN 在删除前失败。第一次结果正确列出“CUE 待核对、BIN 待清理”。保持磁盘原状并解除 BIN 的失败条件，点击继续，目录校验报“引用目录在预览后变化”，BIN 仍然存在。把 CUE 放回后才可以继续。

**涉及调用方与修复建议**　在核对目录快照和引用文档时，允许本次任务明确登记为待核对的源路径缺席。将例外限定于登记的具体路径，其他文件变化和新增引用仍需按原逻辑检查；待核对路径不得重新成为删除目标。[范围校验与后续执行](../src/chd_deploy.py) · [回归用例](../tests/python/test_chd_deploy.py)

**验收**

- [ ] 不放回 CUE，继续清理成功处理 BIN；磁盘上的 BIN 已移除，最终结果仍保留 CUE 待核对及原因。
- [ ] 放回同内容的 CUE 后继续，只处理 BIN，放回的文件完整。
- [ ] 在继续前新增一份引用 BIN 的描述文件，系统仍能发现范围变化并保留 BIN。

## R6-03 · 首次部署仍有待核对项时返回完成，并给出确定空间值

**复现与影响**　使 CUE 的删除结果待核对，BIN 正常清理。首次部署返回 `status=completed`，同时带有一条 `unverified` 和数值型 `actual_image_delta_bytes`。界面提示用户核对，API 却向调用方宣告完成，并提供了尚不能确定的实际空间变化。

**涉及调用方与修复建议**　首次部署和继续清理应使用一致的结果语义。仍有待核对项时，保留已验证的引用切换和已删文件，返回待核对明细，并将实际空间变化标为未知。同步检查部署 API 对“部分完成且无可继续项”的处理，使界面能够收到完整结果。[首次部署与后续结果](../src/chd_deploy.py) · [部署 API](../src/api_chd.py) · [结果展示](../src/templates/chd-deployment.js)

**验收**

- [ ] 通过公开部署 API 复现“仅剩一项待核对”，确认结果表达部分完成、空间变化未知，并保留路径和原因。窗口提示待核对数量，不显示可自动删除该文件的入口。
- [ ] 所有删除均已核实时，仍返回完成状态和正确空间值；正常部署与继续清理的 API、界面含义一致。

## R6-04 · 原请求移出最近任务列表后，窗口无法取回结果

**复现与影响**　模拟清理请求已到达服务端、提交响应丢失，随后创建 30 个更新的任务。原任务及后续清理标识仍保存在服务端，但桌面快照只返回最近 30 项，点击“核对清理结果”无法命中原请求。

**涉及调用方与修复建议**　让服务端能按本次请求标识精确查询对应清理任务，并核对其所属的原清理任务。桌面最近列表继续服务于展示。窗口在收到结果后仍须校验当前游戏和请求，防止切换记录后的旧响应污染新窗口。[请求登记](../src/api_chd.py) · [任务存储](../src/job_manager.py) · [桌面快照](../src/api_desktop.py) · [窗口核对](../src/templates/chd-deployment.js)

**验收**

- [ ] 原任务移出最近 30 项后，恢复连接并从原窗口核对，能取回该任务的真实状态、剩余项及后续标识，核对过程没有新增删除请求。
- [ ] 有多条同名任务时仍只匹配本次请求。延迟 A 的响应、切换到 B，B 的明细和按钮保持正确。
- [ ] 服务端无法确认该请求时，窗口保留待确认状态，不推断任务未执行，也不重复提交清理。

## R6-05 · 只读核对模式下按钮仍保留删除操作的无障碍名称

**现状与影响**　进入核对模式时，代码用 `textContent` 替换了整个按钮内容，移除了 SVG。按钮仍使用固定宽度的图标按钮样式，悬停说明和读屏名称也仍是“继续清理原镜像”。用户难以判断点击后会查询结果还是执行删除。

**涉及调用方与修复建议**　保留项目的标准 SVG 图标容器，使用现有图标机制，按动作一起更新图标、可见提示、`title` 和 `aria-label`，沿用已有中英文机制。核对出有效后续任务时，再将控件切回继续清理状态。[按钮模板](../src/templates/plcn.html) · [状态切换](../src/templates/chd-deployment.js) · [图标按钮样式](../src/templates/workbench.css)

**验收**

- [ ] 在中文和英文下分别核对两种状态。核对模式的图标、悬停和读屏提示都表达只读查询，点击仅发起核对请求。
- [ ] 取得有效后续标识后，图标和名称同步切回继续清理；键盘操作与鼠标操作触发相同动作，固定宽度按钮保留 SVG。
