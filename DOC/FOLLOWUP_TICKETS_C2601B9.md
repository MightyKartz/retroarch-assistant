## R8-01 · 将获准删除的 MTP 对象 ID 保留到最后一次清理

**优先级与影响**　P1，待修复，关联 R7-01。建议发布前完成。用户将同名、同内容的 CUE 放回原路径后，后续清理仍可能删除这份恢复文件。两个场景均通过公开部署和继续清理入口、配合模拟 MTP 设备复现。对象 ID 与删除调用来自模拟设备记录，尚未经真机验证。

### 复现

准备一个待清理的 CUE 和一个可以稍后安全清理的 BIN。设原 CUE 的对象 ID 为 `3`，放回的 CUE 路径与字节均相同，对象 ID 为 `5499`。

| 场景 | 操作顺序 | 当前结果 |
| --- | --- | --- |
| A · 两次回读之间放回 | 删除原 CUE。设备层回读确认路径为空后、部署层再次回读前，放回新 CUE，再执行后续清理。 | 外层发现文件存在，将 CUE 重新列为待删。重试向 `5499` 发出删除指令。 |
| B · 两次清理之间放回 | 首次删除失败，设备层回读确认原对象 `3` 仍在。生成待删清单后，用新 CUE 替换原文件，再点击「继续清理」。 | 路径与指纹校验通过，后续任务删除了 `5499`。 |

### 涉及调用方与修复建议

- **首次部署与后续清单。** 在服务端记录获准删除的原 MTP 对象 ID，并在每次签发剩余清单时沿用这个 ID。设备层已确认原对象消失后，若外层回读发现路径重新出现，将其列为待核对并报告原因。[部署执行与清单生成](../src/chd_deploy.py) · [后续任务签发](../src/api_chd.py)
- **实际删除入口。** 首次及后续执行删除时，同时检查现有的引用范围、内容指纹和原对象 ID。当前对象 ID 已变化或无法确认时，保留文件，从后续自动删除清单中排除该路径，并沿用现有待核对明细。[文件操作边界](../src/chd_io.py) · [MTP 删除与回读](../src/mtp_runtime.py)
