# C-03n 游戏文件双批导入与目录导航反馈修复工单

**优先级 P2**　连续拖入两批文件时，目录导航成功后可能丢失其中一批的反馈。两条失败场景均已在隔离 Chromium 中复现。审查基线为 `b3b00c2` 上包含 C-03m 的工作区，`game-files.js` 和 `browser_smoke.cjs` 的 SHA-256 前缀分别为 `d6b6c00597a7` 和 `37f779d715e5`。[上一轮工单](GAME_FILES_ENHANCEMENT_FINDER_QUEUE_EXPIRY_FEEDBACK_FOLLOWUP.md)

## 复现与验收矩阵

在临时目录 `/Roms/A` 匹配两批内容不同的文件。让第一批正常写入，暂缓写入后发出的目录刷新响应。通过目录行进入子目录 `/Roms/A/B`，确认新目录读取请求已经发出。分别控制旧刷新和新导航的结算顺序，每格使用独立的文件和目录。

| 新导航结果 | 先结算的请求 | 基线表现 | 修复后验收 |
| --- | --- | --- | --- |
| 成功 | 旧刷新 | 只恢复第一批写入摘要，第二批失效原因消失 | 页面进入 `/Roms/A/B`，第一批写入结果和第二批失效原因均可查 |
| 成功 | 新导航 | 第二批的失效提示盖掉第一批写入摘要 | 页面进入 `/Roms/A/B`，第一批写入结果和第二批失效原因均可查 |
| 失败 | 旧刷新 | 具体读取错误和两批反馈均可查 | 保留具体读取错误和两批反馈 |
| 失败 | 新导航 | 具体读取错误和两批反馈均可查 | 保留具体读取错误和两批反馈 |

四格均须断言总计只有一次导入提交，来源和落点归属第一批，目标字节正确，第二批目标文件不存在。恢复目录读取并返回目标目录后，列表显示第一批文件，提交次数保持为一，已结算的提示不会在后续导航重播。

## 实施顺序

1. **先补齐测试。** 在现有 Chromium 回归中复用双批场景，参数化导航结果及结算顺序。用显式等待点确认两批已匹配、第一批已写入、旧刷新与新导航已发出，再按矩阵释放响应。记录基线两格通过、两格失败，以及失败时具体丢失的反馈。[既有双批回归](../tests/browser_smoke.cjs#L1532)
2. **统一反馈更新。** 目录读取更新当前导航及其错误状态，导入队列记录每批的写入结果或失效原因。由单一呈现入口依据这些状态更新状态栏和操作详情。复用现有视图、请求和批次的归属校验，使迟到响应只更新仍有效的状态。成功和失败均保留已结算的两批反馈，导航失败时具体读取错误继续可见。[批次结算](../src/templates/game-files.js#L504) · [失效提示与写入反馈](../src/templates/game-files.js#L804) · [导航与刷新结算](../src/templates/game-files.js#L965)
3. **复验恢复流程。** 跑完四格并检查实际文件与请求次数。继续复验同目录及不同目录的有效批次串行写入，并在恢复读取后检查旧反馈的清理时机。[连续批次回归](../tests/browser_smoke.cjs#L745) · [恢复导航回归](../tests/browser_smoke.cjs#L1606)

实现涉及 `src/templates/game-files.js` 的反馈更新及对应浏览器测试。使用真实导入核对字节，用受控响应复现时序。
