# 游戏文件增强收尾主工单

本单汇总仍开放的修复、各操作链必须维持的约束，以及可以关闭工单的证据。当前基线是 `b3b00c2` 上的未提交增强与三轮修复。此前工单保留复现历史，本单作为下一轮实施和复审的入口。[原实施工单](GAME_FILES_ENHANCEMENT_TICKETS.md) · [三轮复审工单](GAME_FILES_ENHANCEMENT_REVIEW_ROUND3.md)

## 为什么此前反复出现问题

- ExFAT 上的创建、写入、刷新、身份复核和失败清理是同一次导入的连续阶段，之前的回归分别验证了几个时点。文件成功占名后，清理仍可能对后来出现在同一路径的文件发出删除。目录替换增加摘要后，逐个读取也仍可能把不同时刻看到的成员合成一个校验结果。
- Finder 页面已经能核对回调所属的落点。原生来源端仍按文件名、大小和记录时间猜测批次。时间窗口缩短了旧记录的寿命，缺少本次采集时仍没有证据说明剩余记录属于当前事件。
- 717 项 pytest 和 170 项 Node 测试记录了已覆盖的行为。上一轮仍能在真实 ExFAT 上复现两项数据丢失，应用包自检也只证明可以运行自检，Finder 端到端和实体 MTP 依然缺少验收记录。

| B · 审核后的目录替换 | P1 | GF-04-R3 在逐成员复核过程中仍能丢失新内容 |

## A · 无覆盖发布到部分结果

**行为契约**　源文件先暂存，目标同名时保留外部内容。发布的写入、刷新和清理均针对本任务能确认归属的对象。仅依据同一路径上的先前身份检查，无法授权稍后的删除。无法安全清理时保留该路径并报告原因。缓冲刷新失败时，结果明确反映失败与可核对残留。目录部分完成时，任务结果记录实际写入路径、保留的冲突项与中断原因，窗口提供完整明细。[本地发布与导入](../src/game_file_actions.py) · [结果展示](../src/templates/game-files.js)

- [ ] **实际 ExFAT，发布和清理。** 在最终占名之前插入同名文件或空目录。占名之后分别换入外部文件、插入同名子文件。在写入失败后的最终清理处再换入外部文件。逐项核对外部字节仍完整，结果状态和实际输出对应。
- [ ] **缓冲写入失败。** 在最后一次刷新注入磁盘空间不足。任务返回失败或准确的部分结果，目标零字节或截断时无复制成功记录。普通文件与目录导入核对内容和成功结果。
- [ ] **部分输出。** 第一个子文件发布后，第二个子文件遇到同名或写入失败。窗口能查到已写入文件、真实目标、保留项和原因，未执行项有明确状态。保留批量粘贴完整明细的既有回归。

## B · 审核后的目录替换

**行为契约**　用户授权替换的范围绑定到已核对的目标身份与内容。在不可逆清理前，对实际将被移除的对象取得一致证据。按顺序读出的成员摘要只在能确认目录在读取期间保持一致时有效。如果目标变化、出现外部占用，或当前存储无法证明可安全完成，就保留相关内容，给出变化原因和可核对位置。回退也须保留后来出现的对象。[目标校验与替换](../src/game_file_actions.py)

- [ ] **实际 ExFAT，内容变化。** 保留原有反例，预览后原地改写等长文件且时间戳相同。在计算第二个成员摘要时修改已读取的第一个成员，再分别核对变化期间和失败回退后的结果。更新后的文件均有可核对的保留位置，结果与实际发布范围一致。
- [ ] **替换与恢复。** 原目标可完整核对且未变化时完成替换。切换阶段新增独立目标时保留其内容。恢复失败时返回真实的原件、暂存件或新件位置。
- [ ] **兼容回归。** 证据完整且未变化的嵌套 MTP 目录仍能替换。成员对象 ID 变化或存储无法提供足够依据时，保留目标并报告原因。用模拟设备锁定分支结果，记录实体 MTP 验收范围。

## C · Finder 来源与落点绑定

**行为契约**　仅当原生文件 URL、DOM 放下事件与前端落点均能关联到同一次拖放时，才提交导入预览。文件名、大小和时间可用于交叉核对，无法单独确认来源。当前会话缺少该次采集时，提示使用「添加游戏」。旧回调不会触发新目录的预览，也不会消费新落点。[原生桥接](../src/desktop_window.py) · [前端落点](../src/templates/game-files.js)

- [ ] **来源缺失与乱序。** A 和 B 两批文件同名等长、内容不同。B 的原生采集缺失，A 的记录一秒前产生。B 无导入请求，其他有效记录仍可用于自己的事件。覆盖两批均有效但回调反序、页面关闭重开和跨目录拖放。
- [ ] **实际 macOS 应用包。** 从 Finder 拖入单文件、多文件和目录，覆盖中文、空格、字面量 `%20`、不同目录的同名文件，以及选择一个文件夹作为落点。以实际目标路径和字节确认结果。同一批源通过文件选择入口得到等效导入结果。

## 关闭标准

- 实施交付逐项列出改动位置、触发阶段、实际输入与输出或磁盘状态。**先验证问题在修复前可以触发，再用同一用例验证修复后结果。** 磁盘故障用可控测试钩子，记录精确注入阶段，避免靠等待时间碰运气。
- 自动化回归同时覆盖正常成功、拒绝、部分完成和失败清理。按 [AGENTS.md](../AGENTS.md) 清理 AppleDouble 后运行全量 pytest、Node 和 JavaScript 检查。附实际 ExFAT 和 macOS 应用包的独立证据。应用包自检单独记录。[文件操作测试](../tests/python/test_game_file_ops.py) · [文件页测试](../tests/game_files_state.test.cjs) · [浏览器冒烟](../tests/browser_smoke.cjs)
- 两项 P1 的真实 ExFAT 反例通过前，合并建议维持暂缓。真实 Finder 或实体 MTP 条件缺失时，记录已通过的模拟范围、对应设备和具体待验收项。通过的工单逐项关闭，后续若有新问题，按它是否违反本单的行为契约和实际影响单独判断。
