## C-03a · 写入期间到达的有效来源无法排队

**复现与影响**　第二批已在同一浏览页落下，关联标识有效。让第一批进入写入、`changing` 变为真，再送达第二批来源。当前 `acceptPaths` 把写入忙碌传给落点校验，第二批被判定失效并已从待配对记录移除。窗口要求重新拖入，队列没有收到该批。

**修复建议**　来源匹配时核对事件归属和页面导航状态，接收仍有效的批次。把写入互斥放在队列执行阶段，前一批完成或取消后再校验、执行下一批。保留缺少可信关联和落点真实失效时的反馈。

- [ ] 第二批先落下，在第一批写入仍未结束时再送达有效来源。第二批进入等待，第一批结束后两批各写入一次，实际路径和字节正确。
- [ ] 第一批确认、关闭冲突弹窗或取消任务后，仍有效的第二批可以继续。重复的来源回调不会增加写入次数。

## C-03b · 自动刷新使兄弟目录批次失效

**复现与影响**　在父目录 `Roms/` 下向 `A/` 与 `B/` 各拖一批，让两批都进入队列。A 写完后，`submitAdd` 调用 `loadDirectory('/Roms/A')` 刷新写入目标。该路径不同于当前父目录，加载逻辑增加导航版本并清除待配对记录，随后 B 被判定失效。用户没有主动切换目录。现有浏览器回归的两批目标相同，且后台写入使用模拟结果。[现有浏览器回归](../tests/browser_smoke.cjs)

**修复建议**　区分写入完成后的数据更新与用户发起的目录导航。写入子目录后，以当前浏览位置为准更新该视图，或刷新仍有效的相关数据。自动刷新无需废弃兄弟目录的有效批次。

- [ ] 在同一父目录的两个兄弟目录上完成两次放下，逆序送达来源。实际写入分别落到 A、B，各发生一次，最终字节正确，第一批完成后的刷新不清除第二批。
- [ ] 同目录两批的现有串行回归继续通过。仍可用正常导航主动进入子目录，主动导航会使旧浏览上下文下等待中的批次失效。

## C-03c · 导航后迟到预览仍会触发旧目录写入

**复现与影响**　给 A 发起导入预览并延迟响应。在响应返回前，用户导航到另一个目录。无冲突预览随后返回，`confirmAdd` 只校验页面实例仍打开，直接向 A 提交写入。写入结束后，自动刷新还会把页面带回 A。

**修复建议**　让单批的导航上下文随预览和确认传递。在预览返回、打开冲突确认及真正提交写入前，重新核对原批次仍有效。失效时结束该批并反馈，保留当前浏览位置。已经提交的任务按现有取消规则处理，完成时只更新仍相关的视图。

- [ ] 延迟 A 的无冲突预览，主动切换目录后再返回响应。没有针对 A 的写入请求，窗口留在新目录，并反馈旧批次已失效。
- [ ] 延迟有冲突的预览，复验导航后不会打开旧确认弹窗。提交前页面上下文失效时，确认动作也不会触发旧写入。
- [ ] 已发出的写入在用户查看其他目录时完成，结果仍可查，页面没有被带回旧目录。同目录自动刷新不触发上述失效条件。
