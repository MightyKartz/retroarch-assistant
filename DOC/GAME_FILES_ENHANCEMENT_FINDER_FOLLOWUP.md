## C-02 · Finder 拖放会卡住 AppKit 主线程

**复现与影响**　`performDragOperation_` 在 AppKit 主线程调用 `window.evaluate_js`。项目锁定的 pywebview 6.2.1 Cocoa 实现通过 `AppHelper.callAfter` 把 JavaScript 求值排入主线程，同时在调用线程等待信号量。用该 Cocoa 实现和实际 AppKit 事件循环复现时，主线程卡在信号量等待，测试进程由超时监控退出。该等待发生在原始拖放处理函数返回之前，能阻塞应用界面。[原生拖放回调](../src/desktop_window.py) · [桌面依赖版本](../requirements-desktop.txt)

**修复建议**　让原生回调仅采集本次来源并触发异步交付。异步结果仍使用这次拖放的关联标识，兼容来源先到与落点先到。若选择 pywebview 的其他入口，核对锁定版本在 Cocoa 下的实际调用语义，确保主线程没有等待由自身执行的回调。

- [ ] 在 AppKit 主线程上执行可控探针，验证拖放回调返回且事件循环可继续处理后续事件。即使 JavaScript 求值或回传延迟，界面也保持响应。
- [ ] 在实际 macOS 应用包里使用 Finder 拖入单文件、多文件及目录。确认应用保持响应，每个有效批次只进入一次预览或导入，文件选择器仍可用。

## C-01 · 无本次 nonce 的回调仍能借用旧来源

**复现与影响**　B 缺少原生采集，队列中只有 20 毫秒前带 nonce 的 A。两份文件同名、等长、内容不同。调用当前实际 `on_drop` 后，时间回退仍找到并消费 A，将 A 的路径和 B 的事件时间发给前端。页面时间戳校验会将该路径视为 B 的来源。[时间回退与路径转发](../src/desktop_window.py) · [页面落点处理](../src/templates/game-files.js)

**修复建议**　只有能证明本次原生来源与 DOM 落点属于同一次拖放的结果才进入导入。关联缺失时给出「添加游戏」提示，保留其他有效事件的记录。时间、文件名和大小可用于诊断或辅助核对，不能授权导入。

- [ ] 以 20、100、500 毫秒重跑缺本次采集的用例。B 均无导入预览或写入请求，A 的采集未被消费，页面显示文件选择器提示。
- [ ] 有效的同一次拖放在异步回传延迟下仍能完成关联。原生关联无法传到页面时安全回退，字面量 `%20`、中文、空格和同名来源用例继续通过。

## C-03 · 两次有效拖放回调逆序时第一批丢失

**复现与影响**　用实际前端处理函数让 A、B 分别落到同一个浏览页中的两个文件夹。两个 DOM 事件依次到达，再按 B、A 顺序发送各自有效的 nonce 和路径。B 正常提交，A 的落点被单一 `dropZone` 覆盖，A 的来源留在待处理表并最终过期。[落点记录与来源消费](../src/templates/game-files.js)

**修复建议**　按同一次拖放的 nonce 保存来源及已确认落点，匹配成功后只消费该事件的记录。需要序列化导入时保留已匹配且仍有效的批次，在当前任务结束后继续处理。导航、关闭页面和失效回调继续按原有范围校验。

- [ ] 固定顺序为 A 落下、B 落下、B 回传、A 回传。两批各提交一次，源路径和文件夹落点分别正确。重复回调不会额外发起预览。
- [ ] 覆盖来源先到、落点先到、关闭重开及导航后迟到回调。失效记录没有提交导入，也没有清除其他仍有效的落点。

## B-04 · 批量替换只展示前四个原件保留路径

**复现与影响**　一次替换五项并各自保留原件。实际中英文汇总仅显示前四条和总数，而结果明细只读取失败项。确认弹窗承诺完成后可查看保留路径，第五份原件在当前窗口无入口可查。[导入结果汇总与明细](../src/templates/game-files.js)

**修复建议**　保留简短汇总，在现有完整明细入口展示全部保留路径、对应项目和保留原因，同一批次的失败或部分写入继续可查。

- [ ] 在中英文界面分别测试至少五项替换。用户可打开明细查看每份原件的真实保留路径和原因，并与磁盘状态逐项对应。
- [ ] 测试同时包含成功替换、部分失败和无残留的批次。原件保留信息与已写入文件、保留冲突和中断原因均正确展示。
