# C-03l 游戏文件排队批次覆盖目录读取错误修复工单

**优先级 P2**　导航失败后，排队批次的落点失效提示会覆盖具体读取错误。审查基线为 `b3b00c2` 上包含 C-03k 实现的工作区，`game-files.js` 的 SHA-256 前缀为 `8957a5b4eafd`。C-03k 的两种单批响应顺序均已通过，本工单覆盖同一页面还有第二批等待处理的情况。[上一轮工单](GAME_FILES_ENHANCEMENT_WRITE_NAVIGATION_FAILURE_FOLLOWUP.md)

## 复现与影响

1. 打开临时目录 `/Roms/A`，准备内容不同的两个文件。依次拖入两批，在第一批预览返回前让两批来源与落点都完成匹配，第二批进入队列。
2. 让第一批完成真实写入，暂缓随即发出的 `/Roms/A` 目录刷新响应。此时通过目录行进入子目录 `/Roms/A/B`，让该读取先失败，例如返回 `folder B unreadable`。确认页面已经显示具体读取错误。
3. 释放第一批的旧刷新响应，等待队列处理完第二批。旧刷新按预期失效，第一批写入明细仍可查，第二批没有提交。最终状态栏却变成「放置位置已失效，请重新拖入」，先前的目录读取错误消失。

问题已通过实际前端函数的受控时序和隔离 Chromium 测试复现。浏览器用例沿用 C-03k 的第一种响应顺序，在同一轮事件中再送入一批已匹配文件，原有的「导航读取错误仍可见」断言失败。[队列失效处理](../src/templates/game-files.js#L502) · [写入结果呈现](../src/templates/game-files.js#L800) · [单批浏览器回归](../tests/browser_smoke.cjs#L1477)

## 修复建议

复用当前目录读取错误的状态，让它在对应导航失败后保持可见。第二批仍应出队并显示落点失效提示，可在已有结果区域提供明确反馈。保留第一批已完成的摘要和明细。检查队列入口、预览返回和确认提交处的落点失效提示是否遵循相同规则，避免异步回调覆盖仍有效的读取错误。[目录读取失败](../src/templates/game-files.js#L972) · [批次匹配入口](../src/templates/game-files.js#L464)

## 验收条件

- [ ] **双批且新导航先失败。** 用显式等待点确认两批已匹配、第一批写入已完成、目录错误已显示，再释放旧刷新。队列处理完后，具体读取错误仍可见，第一批结果可展开，第二批有明确的落点失效反馈。
- [ ] **只写入第一批。** 断言总计只有一次导入提交，来源与落点正确。核对第一批目标字节和第二批目标路径的文件状态。恢复读取并导航后，列表反映已完成的写入，旧结果不会重播，写入次数保持为一。
- [ ] **既有行为。** C-03k 的两种单批响应顺序继续通过。目录读取正常时，失效批次仍有提示。同目录或兄弟目录中仍有效的连续批次继续依序写入。[此前批次回归](../tests/browser_smoke.cjs#L745)
